# 正式开发第三批：实时预览与双向源码定位

日期：2026-11-05。分支：`feature/electron-desktop`。独立版本：`0.1.0-alpha.3`。

本批继续实现[获批的设计 V1.0](design/PRODUCT_DESIGN.zh-CN.md)，没有修改冻结评审样稿。应用仍处于正式开发的 Alpha 阶段，25 项保留功能尚未全部完成。

## 本批功能与交互

- 默认启用实时预览：停止输入约 450 ms 后更新。150 ms 的草稿暂存与预览分开，源码保存仍须显式操作，不因预览而写入源文件。
- 自动预览期间继续允许编辑和切换标签。输入或导航时取消旧任务；前台预览串行运行，只有文档 ID、内容版本及输入代次均匹配的结果才能开启导出或行定位。
- 输入法 composition 事件期间暂停启动预览，结束后更新。该行为经过合成事件验证，尚未完成所有系统输入法的人工验收。
- 原有“更新预览”按钮保留；设置中可独立关闭实时预览或分栏滚动同步，并持久化。外观、预览和同步设置部分更新时互相保留，非法字段/类型被拒绝。
- 双击普通预览文字定位并聚焦源码，双击源码或点击“定位预览”定位正文；文档菜单的“定位当前段落源码”定位当前阅读区域。源码与渲染块统一转换为界面使用的 1 起始行号，并修正搜索定位原有的 0/1 行号边界。
- 分栏滚动按源码行与渲染块位置双向联动；程序触发的目标滚动暂时抑制反向反馈。用户的新滚轮、指针或键盘操作可以接管主导面板。
- 自动更新后按源码行/阅读位置恢复视口，不重新加载旧的持久化阅读位置。渲染期间继续滚动时，完成后遵循最新源码视口或新的正文操作，避免旧锚点拉回位置。表格、长段、公式和图表内部按块高度近似映射，不承诺字符级或视觉像素逐行对齐。
- 旧预览、渲染中或未确认的修改不能导出或进行行映射。缺失图片等预览失败明确显示，可继续编辑并在下一次有效输入后恢复；同一失败输入不会无限重试。
- 保存冲突等文件操作错误不会被定时预览成功消息覆盖，防止用户遗漏未保存状态。
- 设置窗口关闭后恢复原触发点，但用户已经选择新的焦点时不再抢回；自动测试等待原生 close 事件完成后继续输入。

## 实现与隔离

`renderer.js` 分离文件导航与自动预览编排，维护取消代次、串行任务、当前修订和失败重试边界；自动预览不使用导航的编辑锁。导航先取消并等待旧预览退出，再改变当前文档，避免共享渲染上下文交叉写入。

`viewer.ts` 使用共享 `AsyncTaskManager` 取消文本/图表回调，继续复用正式 Markdown 引擎；`desktop:cancel-preview` 仅取消前台窗口所有者的图表任务，不取消独立导出所有者。没有替换共享渲染核心或新增模拟渲染器。

`editor.ts` 基于 CodeMirror 的 selection、viewport、scrollIntoView 和 composition 状态实现源码端能力；`viewer.ts` 使用 `.md-block` 的 0 起始 `data-line`/`data-line-count` 完成渲染端映射。CodeMirror 会虚拟化长文 DOM，因此不通过文本行 DOM 数量推算全部源码行。参考 [CodeMirror 官方 API 文档](https://codemirror.net/docs/ref/)。

双击链接、按钮、输入框、SVG 或 Canvas 等交互元素时不抢占其操作；仍可通过文档菜单定位所在阅读区域的源码。设置只接受 appearance、livePreview、scrollSync 三个键，不扩大文件路径或资源权限。

## 验证

最终开发入口与实际 `documd-desktop.exe` 完整回归均为 **76/76** 通过，无跳过。

`npm run typecheck`：项目源码 0 错误，既有 297 条源码分发 vendor 诊断仍单独报告。构建、脚本语法及 `git diff --check` 通过。独立 Windows x64 包使用 SHA-256 校验通过的匹配 Electron ZIP 生成；包内版本 `0.1.0-alpha.3` 及主进程、preload、界面、编辑器和预览资产哈希与最终候选构建一致。打包工具未进入 app.asar，冻结样稿哈希保持不变。

新增 `test/live-preview-e2e.test.js` 的 9 个子测试与父测试，共 10 个报告条目。在真实 Electron 中验证：

1. 防抖仅显示最新输入、预览不写源文件、合成 composition 组字期间暂停。
2. 暂挂真实图表工作进程后仍可输入；旧进程实际销毁，新图表 PNG 完成且最新修订可导出。
3. 图表任务运行中切换标签，目标文档不被旧结果覆盖，再切回保留草稿。
4. 图片缺失失败后编辑器可用、导出关闭，修正内容后自动恢复。
5. 保存冲突错误经过预览定时窗口后仍明确显示，外部磁盘内容不被覆盖。
6. 带 frontmatter、围栏代码和 100 个章节的文档，双击正反向行号匹配。
7. 双向滚动行映射、位置稳定无反复跳动、关闭同步后面板可独立滚动。
8. 慢速图表任务运行中滚动源码或操作正文，渲染完成后保留最新操作意图并恢复两侧对齐。
9. 预览/同步设置重载后持久化、外观不被覆盖、非法设置拒绝，关闭自动预览后手动更新仍可用。

图表测试只暂挂实际工作进程，随后仍执行真实渲染；没有使用模拟 PNG 代替图表结果。系统文件对话框与关闭确认继续由测试桩返回；预览、IPC、文件读写、渲染、导出等运行实际代码。

## 本批边界及后续

- 本批没有新增依赖；Alpha 2 报告记录的构建工具依赖审计问题尚未处理，不能宣称依赖风险已清零。
- 目前前台 Markdown 仍会重新渲染；复杂超长文档性能、连续输入成本、增量保留视图与异步本地依赖变化仍需专项验证。防抖是交互策略，不是渲染耗时承诺。
- 双向同步采用块内近似映射；折叠代码、空白行、隐藏 frontmatter、段落换行和复杂图表可能存在视觉位置偏差。没有声称所有主题/字号/折叠组合都完成验收。
- 未命名文档、单实例/文件关联/拖放、批注、完整设置、其他保留导出与 Slidev 等按[开发计划](DEVELOPMENT_PLAN.zh-CN.md)继续；功能矩阵不因此整体标记完成。
- 尚未进行干净 Windows、实际 Office、全部系统输入法、高 DPI/读屏和长文性能验收；未重跑 Chrome/VS Code/移动端/fibjs 全套回归。
