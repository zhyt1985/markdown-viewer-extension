# 正式开发第四批：单实例与桌面打开入口

日期：2026-11-05。分支：`feature/electron-desktop`。版本：`0.1.0-alpha.4`。

按用户确认的后续计划，补齐单实例、文件/文件夹拖放和系统文件打开参数。继续沿用获批设计 V1.0；没有修改冻结评审样稿。当前仍为 Alpha，完整 P2 与 25 项保留功能尚未全部验收。

## 功能及操作行为

- 应用按数据目录申请 Electron 单实例锁；第二个使用相同目录的进程将文件请求交给现有实例，然后退出。主窗口最小化时恢复窗口；无文件参数时激活窗口。
- 冷启动及系统“打开方式”传入的本机路径均进入打开队列。支持多个文件、相对路径的调用方工作目录、中文、空格、`#`、`%`。这是界面内打开文档，不提供命令行转换或自动化功能。
- 将本机 Markdown 文件或文件夹拖到窗口中，显示统一拖放提示；文件进入标签页，文件夹注册为工作区。重复文件/文件夹复用现有条目。
- 文件拖放在捕获阶段处理，阻止 CodeMirror 将拖入文件的内容插入当前源码。普通编辑器文字拖动保持原有处理路径；窗口其他位置的文本或网址拖放不会导航。
- 通过 preload 的 `webUtils.getPathForFile` 从原生 File 对象提取路径；网页传入字符串、合成 File 或网址不能据此获得任意本机路径授权。没有增加任意路径打开 API。
- 外部请求先排队，待编辑稿同步和阅读状态保存后执行。原生文件对话框未结束时不切换文档；关闭确认取消后继续处理请求。输入法组字期间也暂缓切换。
- 重复打开脏文档复用原标签和编辑稿，不从磁盘覆盖未保存文本，也不自动将其扩大到新工作区的资源范围。
- 同批包含无效路径、不支持类型、无效 UTF-8 等时保留有效输入，对失败条目显示独立、可关闭的提示。全部无效时保留活动文档。打开新文件不写旧源文件。

## 实现与限制

`open-inbox.cjs` 负责启动参数、本机路径检查、opaque 请求标识和队列。每次最多 32 项、最多 16 个待处理请求，单路径不超过 32768 字符；队列超限显示提示，不静默挤掉旧请求。已打开文档/工作区继续沿用各 32 项上限，Markdown 继续限制为 10 MiB。

开发启动可能将调试选项放在应用目录之前，因此解析时先识别 Electron 选项，再跳过开发应用入口；不能简单假定应用路径固定在 argv[1]。第二进程使用 additionalData 传递本进程解析后的路径和工作目录，避免依赖 Electron 对 argv 的重新排序。

主进程接收系统请求或由真实 File 对象提取的路径，随后仍执行规范路径、文件类型、编码、大小、工作区与文档修订检查。渲染进程只取得待处理请求的标识/数量，通过标识消费请求；伪造或已消费标识被拒绝。导航、图表与导出的已有隔离保持不变。

URL、file URL 和显式 UNC 输入被拒绝；未将本批视为所有映射盘/reparse point 情形的最终远程资源审计。输入文件夹不递归批量打开其中的文件，不增加整书导出或 CLI 批量转换。

参考 [Electron 单实例 API](https://www.electronjs.org/docs/latest/api/app#apprequestsingleinstancelockadditionaldata) 和 [webUtils 官方文档](https://www.electronjs.org/docs/latest/api/web-utils)。本批无新增依赖。

`npm run typecheck`：项目源码 0 错误，既有 297 条源码分发 vendor 诊断单独报告。构建、脚本语法及 `git diff --check` 通过。

新增 `open-inbox.test.js` 两项单元测试，及 `open-entry-e2e.test.js` 七个子场景与父测试，共增加 10 个报告条目：

1. 实际冷启动参数打开文件、持有锁，且不把开发应用目录误注册为工作区。
2. 用 Node 启动真实第二进程，核对退出、主窗口恢复、多文件打开及重复脏标签保留；不是手动 emit second-instance 事件。
3. 通过 Chromium CDP 原生拖放事件携带真实本机文件/文件夹，核对 File 对象、工作区复用、编辑稿不变与拖放提示。
4. 混合缺失、无效编码、未知类型和有效文件，核对提示、活动文档及源文件字节。
5. 暂挂原生文件对话框，确认外部打开等到取消对话框后执行，并保留最新编辑。
6. 网页链接、合成 File 与伪造请求标识不能成为路径授权。
7. 暂挂关闭确认，第二进程请求等待；取消关闭后继续打开文件，旧草稿仍在。

单元测试覆盖 Electron 参数位置变化、参数值、`--`、路径与 URL/UNC 区分、请求标识一次消费、数量限制和告警。

系统选择和关闭对话框仍由测试桩返回；实际窗口、第二进程、实例锁、File/webUtils/IPC、文件系统与渲染运行真实代码。拖放使用 CDP，不等同于人工从 Windows 资源管理器操作；系统“打开方式”界面及默认关联注册仍需目标机人工验证。

## 交付边界与后续

- 本批支持文件参数入口，没有修改 Windows 注册表或默认应用，也没有交付安装器。正式文件关联注册留待个人安装/交付阶段。
- 单实例仅协调支持该锁且使用相同数据目录的进程；升级时应先退出旧版本，早期 Alpha 不参与该锁。不同显式 profile 保持隔离。
- 打开队列仅在内存中，不承诺应用崩溃或确认退出后继续处理未消费的请求；草稿恢复仍独立落盘。
- 未命名草稿、首次保存、导航前后退、SUMMARY、编码恢复、完整设置、批注、其他保留格式/导出等继续按[开发计划](DEVELOPMENT_PLAN.zh-CN.md)推进。
- Alpha 2 记录的构建工具依赖审计问题尚未处理。尚未进行干净 Windows、人工资源管理器拖放/文件关联、全部输入法/高 DPI/读屏与真实 Office 验收；未重跑其他平台全套回归。

运行入口：`dist/desktop/packages/documd-desktop-win32-x64/documd-desktop.exe`，需保留整个便携目录。没有执行 Git 提交。
