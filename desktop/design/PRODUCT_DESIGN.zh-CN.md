# docu.md Desktop 产品界面与交互设计

版本：V1.0，2026-11-05。状态：**用户已通过 R0.1 评审，冻结为正式实现的产品设计基线；不代表产品功能已全部完成。** 批准依据及样稿哈希见 [评审记录](APPROVAL.zh-CN.md)。

## 1. 本阶段交付与开发顺序

用户要求正式开发前先完成产品设计。设计已评审通过，现进入以下流程的第 4 步：

1. 信息架构、主工作流、视觉方向和关键状态设计。
2. 可点击样稿与窗口/键盘/外观检查。
3. 用户评审，记录意见并修改；冻结设计 V1.0。
4. 正式工程切换、实现设计组件与布局，再接入已有服务及继续完整功能开发。

本轮只新增 `desktop/design/` 设计材料并调整开发计划/说明，不修改 `desktop/src/` 的产品功能或将样稿直接打包到应用。已有六批功能代码保留作为实现资产，后续按照设计重新装配。

交付包括：本设计文档、[可点击样稿](index.html)、[设计预览说明](README.zh-CN.md)、`previews/` 截图与自动检查记录。样稿使用虚构的本地文档，操作不读写源文件、剪贴板或系统设置。高级菜单中的能力说明不等于对应功能已经接入。

## 2. 产品定位与设计方向

面向个人使用的本地文档工作台，覆盖阅读、整理、编辑、批注与单文档输出。默认阅读优先，同时让编辑和导出容易找到。保留现有计划中的 25 项能力及排除边界，不增加账号、云同步、AI 聊天或在线资料入口。

获批方向为“简洁阅读优先”：浅色中性应用外壳、白色文档、克制的蓝紫强调色、清晰的文字层级。深色外观同步设计；按标准密度实现，紧凑密度细节在对应组件开发时验证。

设计原则：

- 文档占据视觉中心；文件导航、目录和批注形成稳定的空间位置。
- 常用动作直接可见，低频管理进入菜单或设置；同一命令拥有固定归属。
- 应用外观和文档主题独立，文档样式不能污染工具栏、菜单或对话框。
- 状态与动作相邻：文档未保存看标签/状态栏，冲突在文档上方处理，导出进度在任务区查看。
- 快捷键增强效率，每个关键动作仍有可见入口；不可只通过悬停、右键或记忆快捷键完成。
- 用户内容安全优先：取消保留状态，危险操作明确后果，失败保留编辑与重试入口。

## 3. 信息架构与命令归属

| 层级 | 内容 | 固定位置 |
|---|---|---|
| 应用 | 新建、打开文件/文件夹、设置、帮助、快速打开/命令 | 顶部应用栏与菜单 |
| 工作区 | 目录、全文/文件名检索、最近打开、工作区切换/移除 | 左侧活动栏 + 文件侧栏 |
| 文档 | 标签、阅读/分栏/源码、保存、文档外观、专注、导出 | 标签栏 + 单行文档工具栏 |
| 内容 | 标题目录、批注、图片/表格/图表操作 | 右侧辅助面板 + 内容上下文菜单 |
| 任务与状态 | 保存/草稿、编码、缩放、自动刷新、导出任务 | 底部状态栏，按需打开任务浮层 |
| 管理 | 全部配置、语言、缓存、数据备份、快捷键、版本和许可证 | 设置对话框 |

明确撤销原型的平铺工具栏：缓存统计/清理、语言列表、重新载入等低频动作不常驻顶部。导出用一个入口选择格式；不平铺 Word/PDF/HTML/PNG 四个按钮。

主窗口纵向结构：系统窗口边框/标题区 → 应用栏 → 工作区区域 → 状态栏。文档区域内部为标签 → 文档工具栏 → 可选通知 → 正文。应用外层不随正文滚动。

Windows 的系统最小化、最大化和关闭由原生窗口提供，不在内容区重复绘制。设计样稿顶部“界面设计 / 审阅场景”属于评审工具，正式产品不包含这一行。

## 4. 布局与窗口策略

以下为待冻结的设计参数，不是现有产品窗口的已实现规格。

| 区域 | 默认尺寸 | 行为 |
|---|---|---|
| 应用栏 | 48 px | 品牌/应用菜单，中央快速打开，右侧外观与设置 |
| 活动栏 | 48 px | 文件、检索、最近打开；底部任务与快捷键 |
| 文件侧栏 | 236 px，紧凑窗口 212 px | 单独滚动，树按需展开；可收起 |
| 标签栏 | 38 px | 单行，标签过多时横向滚动，不自动换两行 |
| 文档工具栏 | 50 px | 单行，空间不足时将次要操作收入“更多” |
| 目录/批注面板 | 224 px | 宽窗口停靠，窄窗口按需浮出；两者共用一个位置 |
| 状态栏 | 28 px | 不显示大段诊断，不抢占正文高度 |
| 阅读纸面 | 最大 736 px | 可选 640/960；正文通常约 26–40 个汉字一行 |
| 正文内边距 | 28–60 px | 随可用空间收敛；长文居中，不强制横向滚动 |

默认工作窗口建议 1440×900，主要适配 1280×800、1366×768，首版建议最小窗口 960×640。以上按内容逻辑像素设计，Windows 标题边框占用需在正式壳中另计。

响应规则：

- 宽度 ≥1280：文件侧栏和右侧目录可同时停靠；阅读保持居中。
- 1024–1279：默认收起右侧面板；点击目录/批注才以浮层打开，不能缩窗时自动覆盖正文。
- 900–1023：侧栏收窄，隐藏次要路径说明，常用操作仍可见。
- <900：作为高倍缩放/辅助兼容状态，文件侧栏按需浮出；不宣称首版交付移动应用。
- <640：阅读与源码单窗切换，隐藏分栏选项；次要文档操作进入更多菜单。
- 分栏默认 1:1，并收起右侧面板；正式组件提供分隔线拖动、键盘调整及重置。样稿仅演示默认比例，尚未实现拖动。
- 正文、文件树、编辑器和批注独立滚动；打开菜单/按钮不会先把正文滚回顶部。
- 分栏与面板宽度调整、窗口恢复后保持同一源行附近；不单纯以像素作为最终阅读锚点。

间距采用 4 px 基础节奏，常用 8/12/16/24/32。此取向参考 Microsoft 的[内容布局与间距说明](https://learn.microsoft.com/en-us/windows/apps/design/style/spacing)，具体尺寸是本产品的初拟选择。

## 5. 视觉规范

### 5.1 色彩与表面

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `background` | `#F5F6F8` | `#191C23` | 工作台背景 |
| `surface` | `#FFFFFF` | `#222630` | 应用栏、菜单、对话框 |
| `subtle` | `#F9FAFC` | `#1E222B` | 文件导航与次级区域 |
| `text` | `#252B37` | `#E5E9F2` | 主文字 |
| `muted` | `#626D7E` | `#A8B1C2` | 次要说明，仍须可读 |
| `border` | `#E3E7ED` | `#363D4B` | 轻量分隔 |
| `accent` | `#405BD2` | `#A9B8FF` | 当前选择、主动作、键盘焦点 |
| `accent-soft` | `#EDF0FF` | `#303B62` | 低强度选中背景 |
| `success` | `#2B7055` | `#8AD4AD` | 已保存等正向状态 |
| `warning` | `#8A4C12` | `#F2CC89` | 未保存、冲突等需关注状态 |
| `danger` | `#B33043` | `#FFABB6` | 放弃修改、删除等操作 |

应用、文档和批注使用不同 token 层。暖纸主题只改变文档背景/字色；深色应用不强制所有导出成为黑底。批注黄/蓝/绿/粉属于内容标记，不能混作错误状态色。

大面积区域使用纯色和轻分隔，避免渐变、毛玻璃、厚阴影和重复卡片。阴影只用于悬浮菜单/对话框等层级。按钮圆角 6 px、面板/输入 6–8 px、对话框 12 px；不将每个文件行做成独立卡片。

### 5.2 字体、图标与密度

- 应用字体：Windows 系统 UI 字体优先，中文回退 Microsoft YaHei UI；界面默认 13 px，标题/菜单按层级调整，辅助信息至少 11 px。
- 正文默认 16 px、行高 1.85；文档一级标题 30 px、二级 20 px，代码等宽字体 12–13 px。
- 正式编辑器使用真实逻辑行、可调整字号与换行策略；样稿 textarea 只表达布局，行号不构成完整编辑器实现。
- 正文衬线/无衬线、代码主题等由文档主题决定，不跟随修改应用 UI 字体。
- 图标采用同一套 16/18 px 描边风格；常用点击区域 32 px，最小独立目标不低于 24 px；高倍缩放/粗指针另增加有效区域。
- 图标按钮有可访问名称和简短提示；关键危险动作必须显示文字。
- 默认标准密度；紧凑模式只减少行高/间距，不降低正文和关键说明的可读性。

### 5.3 组件状态

按钮、输入、文件行、标签、模式切换、菜单和选项须统一覆盖默认、hover、focus-visible、pressed/selected、disabled、busy、error。选中同时用形状/边线与文字表明，不只靠颜色。加载按钮保持原宽度，防止工具栏跳动；不可操作项给出原因，不以“点击后没反应”表示禁用。

## 6. 核心流程与交互合同

### 6.1 首次打开与恢复

开始页提供“打开文件”“打开文件夹”“新建笔记”，下方为最近记录。没有工作区时左侧说明空状态，不展示假的目录或统计。

再次启动先恢复有效工作区与文档，回到上次阅读位置。失败项汇总为可展开通知，保留有效内容；提供移除失效记录、重新定位文件/文件夹、查看待恢复草稿。恢复期间保留明确进度，不接受会导致状态重入的操作。

拖入多个文件时，预先检查类型和数量；可打开项正常进入标签，失败项集中反馈原因。拖入文件夹形成工作区。文件关联使用单实例接收文件，不额外弹出重复主窗口。

### 6.2 文件、标签与导航

- 文件树按目录优先；文件图标/扩展名体现类型，未知类型显示原因。刷新不丢失当前文档和可保留的展开状态。
- 已打开文件复用标签。标签宽度有限，完整名称通过提示可见；未保存用点和可访问名称标记，不能只修改文件名字符串。
- 标签切换保存编辑稿、选择、滚动和阅读锚点；慢渲染不能覆盖后来选中的文档。
- 右键标签菜单：关闭、关闭其他、关闭右侧、在工作区定位。批量关闭先收集所有未保存文档，逐项或批量处理。
- 打开文档、检索结果、普通本地链接及章节跳转进入导航历史，前进/后退恢复文档与源行。
- `SUMMARY.md` 可切换章节导航；普通 Markdown 链接可跨本地文档并定位锚点。输出范围始终为当前文档，不引入整书导出。
- 关闭工作区说明“关闭关联标签，不删除本地文件”，并处理未保存稿；品牌/开始页入口不关闭已有标签。

### 6.3 阅读、专注与源码

阅读、分栏、源码三个模式固定在文档工具栏左侧。切换保持同一源行附近，不清空选择与批注。编辑模式的保存入口只在需要时显示，状态栏始终给出保存状态。

目录与批注共用右侧位置。专注阅读隐藏两侧导航，保留最小文档控制和明确退出入口，Esc 返回原布局。应用全屏由原生窗口行为处理，与专注模式分开。

图片/图表在独立查看浮层中缩放、平移、复位，Esc 关闭并回到原阅读位置。复制、保存格式在内容上下文菜单里，根据引擎实际输出能力显示；不能用 PNG 假冒 SVG/DrawIO。

### 6.4 编辑与保存

新建文档先形成未命名草稿，首次保存选择路径。正式版本必须有本地草稿暂存和崩溃恢复；“草稿已暂存”和“源文件已保存”是两个不同状态。

分栏使用合并更新的预览，输入时不抢焦点。显示渲染中的内容保留稳定占位；图表加载/错误定位到对应块，不覆盖整篇编辑器。提供查找/替换、行号、软换行、撤销/重做和双向源行定位。

保存成功后才清除未保存标记。失败保留内容和基线，展示用户可执行的处理方式。另存成功切换当前标签到新文件；取消保持原路径和编辑稿。编码/BOM/换行明确可见，不能悄悄用替换字符覆盖无法识别的文本。

关闭确认至少包括“保存并关闭 / 不保存 / 取消”。默认安全操作为取消；有多个文档时展示清单。保存失败或取消另存不能继续关闭。

### 6.5 外部修改与冲突

| 当前状态 | 外部事件 | 界面与后续 |
|---|---|---|
| 无编辑，自动刷新开启 | 文件更新 | 更新正文，保持阅读锚点；短状态提示，不弹模态框 |
| 无编辑，自动刷新暂停 | 文件更新 | 保留当前内容，文档通知提供“重新载入” |
| 有未保存编辑 | 文件更新 | 保留编辑，文档顶部非模态警告；保存时拦截冲突 |
| 编辑稿与磁盘不同 | 点击处理 | 左右对比“我的编辑稿 / 磁盘版本”，可保留编辑、另存副本、二次确认重新载入 |
| 文件删除/不可访问 | 任意状态 | 保留已加载内容/草稿，提供重新定位、重试与另存；不能自动新建覆盖 |
| 所选目录被替换或越界 | 读取/保存 | 清晰告知原授权目录不可用，保留编辑稿；重新选择范围必须走系统选择器 |

不提供默认强制覆盖按钮。自动刷新只控制载入行为，不关闭冲突检查。正式版本监听源文件与已解析的本地依赖；依赖更新不清空源编辑稿。

### 6.6 检索与快速打开

侧栏检索提供文件名/正文切换、查询、当前工作区范围、进度与取消。结果按文件分组，显示行号和片段。点击打开对应文档并定位块；高亮与正文批注采用不同视觉样式。

新查询或切换工作区取消旧查询，迟到结果不回填。扫描达到上限须明确提示“结果不完整，请缩小范围”，不能显示为“没有找到”。权限/编码等跳过项单独计数并可查看。

Ctrl+K 打开文件与命令入口，输入 `>` 切换命令。键盘可上下选择、Enter 打开、Esc 取消；打开后焦点进入目标文档。文内 Ctrl+F/H 与工作区 Ctrl+Shift+F 分开。

### 6.7 批注

选中文本后出现紧凑标记条，支持四种颜色及背景/下划线/波浪线/边框；添加备注后关联右侧批注项。所有工具也可从批注面板访问。

侧栏条目显示引用、备注、位置/时间与操作；点击引用定位正文。删除提供限时撤销。修改正文后无法可靠重定位的批注进入“待重新定位”，用户确认匹配后恢复，不能静默挪到错误段落。

批注菜单包含原格式导入、导出、结构化复制、显示配置。导入先预览新增/重复/无法定位的条目，再确认合并；导出或复制后关闭文档仍需处理正文未保存状态。

### 6.8 导出与内容复制

统一“导出当前文档”对话框按用途选择 Word、PDF、单文件 HTML、PNG。清楚显示来源文件及“包含未保存编辑稿”，配置只显示当前格式相关项。Word 的可编辑公式、PDF 纸张/边距、PNG 清晰度等分别归属对应选项。

选择系统位置后任务进入后台，不阻塞阅读/编辑；不可变快照固定文档和设置版本。任务中心显示准备、资源检查、渲染、写入、完成/失败/取消，支持重试或取消。只有实际写入成功才显示成功并提供打开/定位文件。

缺少图片、错误图表、超时等先定位问题，明确解决或允许用户作出有后果说明的选择，不把不完整产物默认标为成功。取消不留下成功状态或伪完整文件。

表格菜单提供 Office HTML+TSV 复制、TSV、真实 XLSX；图片/图表菜单提供实际支持的 PNG/SVG/DrawIO。批量资产出口列出序号、类型、源行和错误，不合并成整书输出。剪贴板操作成功/失败都有可感知反馈。

### 6.9 其他保留格式

- 独立图表：图形阅读为主，可切换对应源码，导出菜单按引擎能力生成。
- Slidev：演示/列表模式、前后页、页数、全屏；静态导出的限制在导出前说明。
- 本地 HTML：隔离阅读；“转为 Markdown”先预览转换结果再保存，支持本地文件/粘贴，不接受网址。
- 代码/文本：等宽字体与行号，语言/编码可见；图片：缩放与原始比例。未知二进制使用可理解的空状态。
- 本地图片、字体/图表资源越界时可明确选择额外本机资源目录；不开放整个磁盘。

### 6.10 设置、数据与个人交付

设置按常规、外观、阅读与编辑、文件、导出、数据与缓存、快捷键、关于分组。共享 schema 的每个保留设置必须映射到设置项或明确的文档操作，不能因界面简化而丢失能力。

应用外观、文档主题和导出配置分别管理。设置可搜索、恢复默认，破坏性重置先说明影响。缓存统计/清理位于数据页；清理缓存不清理草稿、批注、阅读位置或源文件。

备份/恢复显示包含的数据和目标位置，恢复先预览再确认；手动升级提供数据兼容/回退说明。关于页展示真实独立版本、构建、许可证，不借用扩展版本冒充桌面版本。

## 7. 状态、反馈与键盘规则

| 状态 | 呈现 | 可执行动作 |
|---|---|---|
| 空工作区/无文档 | 开始页、侧栏空状态 | 打开、新建、最近记录 |
| 加载/渲染中 | 局部进度/稳定占位，必要时禁用重入操作 | 取消或切换目标，不整窗冻结 |
| 无匹配结果 | 查询区域内提示 | 改关键字或范围 |
| 扫描截断/部分失败 | 结果摘要与跳过明细 | 缩小范围、查看问题 |
| 未保存/暂存中/已暂存 | 标签 + 状态栏明确区分 | 保存、另存、恢复 |
| 磁盘变化/冲突 | 文档内通知条 | 对比、另存、重新载入 |
| 资源/渲染错误 | 对应内容块/任务明细 | 定位源码、替换资源、重试 |
| 保存/导出失败 | 持续的任务/文档反馈 | 重试、选择其他位置、保留编辑 |
| 完成 | 非阻塞短提示 + 可再次查看的任务结果 | 打开或定位实际产物 |
| 危险关闭/删除 | 说明后果的确认，默认取消；可撤销则提供撤销 | 取消、保存后继续、明确放弃 |

短暂成功提示通常 3–5 秒；需要用户处理的失败/冲突持续保留。错误说明“发生什么 / 当前内容是否保留 / 下一步可做什么”，技术堆栈收进详情。

键盘：Ctrl+N/O/S、Ctrl+Shift+S、Ctrl+W、Ctrl+K、Ctrl+Shift+F、Ctrl+F/H、Ctrl+B、Ctrl+,、Ctrl+Shift+Enter。Esc 只关闭最上层浮层/退出专注，不产生保存或放弃的隐式选择。平台保留快捷键不得被不必要拦截。

模态框打开时焦点进入内部，Tab/Shift+Tab 不离开；关闭后回到触发控件，控件消失则回到合理的文档位置。采用原生 dialog 作为首选实现，并参照 [WAI-ARIA 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。标签用方向键切换并维持可见焦点；不能因为重建 DOM 而把焦点丢回页面根。相关原则见 [WAI 键盘界面说明](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)。

正文主字色、辅助说明和主按钮目标对比度至少 4.5:1；图标/焦点边线需可辨识。支持 200% 放大、深浅外观、减少动态效果；不能仅以自动检测声称已完成读屏验收。多语言长文本、中文输入法、Windows 高对比度和实际读屏测试需在正式组件阶段专项验证。

## 10. 设计评审与退出条件

需用户评审的具体结果：

1. 阅读优先的整体方向、信息密度、强调色及深色外观。
