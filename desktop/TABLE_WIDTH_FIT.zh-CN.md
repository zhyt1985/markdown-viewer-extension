# 表格自身宽度适配

日期：2026-11-06。版本：`0.1.0-alpha.9`。分支：`feature/electron-desktop`。

## 修正上一版的验收遗漏

Alpha 8 只把超宽表格放入局部滚动容器，其表格自身仍可能超过正文宽度。之前的回归只断言正文和阅读区不横向扩张，没有要求 table 及最后一列进入正文边界，因此不足以证明用户报告的问题已完整修复。

Alpha 9 为原生 Markdown 表格单元格、链接和内联代码加入可断词换行，覆盖 nowrap 和最小宽度干扰，保留单元格文本。横向间距按正文实际宽度和列数收紧；只有可用列宽极窄时才进一步响应式减小表格字号。使用 CSS 容器宽度计算，窗口调整和阅读/分栏切换无需重开文件。正常小表继续按内容宽度显示，左对齐、居中和通栏保持可用。

滚动容器保留为不可分割媒体或复杂嵌套内容的兜底，但本批文本表格场景以“表格自身、末列及文字都在正文边界内，无需横向滚动”为通过标准。极窄分栏的密集多列表格会明显增高，可扩大窗口或切回阅读模式改善阅读。

变更只作用于桌面阅读 DOM 和桌面样式；独立 DOCX/PDF 导出主机沿用原有排版。不会写入源文档。冻结设计样稿未修改。

## 验证记录

替换上一版滚动行为断言，直接检查 table 几何宽度、右边界和局部 scrollWidth。新增中文长段落、长 URL、长代码测试，并检查完整文本保留。覆盖 16 列长标识符、小表三种对齐、约 213 px 正文宽度的窄分栏、实时预览和源文件字节保留。

修复前的新断言复现失败：表格约 5040 px，而正文约 724 px；正文自身无横向溢出仍不代表 table 适配。修复后针对性测试 6/6 通过。最终 Alpha 9 开发入口和实际打包 EXE 的完整回归均 **112/112** 通过，无失败或跳过，包含已有 DOCX/PDF、编辑、草稿恢复和章节导航场景。

项目源码类型检查 0 错误；既有源码分发 vendor 包的 297 条诊断单独报告。包内版本和七项关键运行文件哈希与最终构建一致，冻结设计样稿哈希未变，`git diff --check` 通过。已查看开发入口的阅读、长文本和分栏截图，以及实际 EXE 的阅读和长文本截图，确认表格按正文宽度换行。
