## 已接入真实服务的界面

- 应用栏、活动导航、文件侧栏、单行标签、文档工具栏、独立正文/源码区域与状态栏，按获批的阅读优先结构实现。
- 文件菜单承载打开文件/文件夹、保存和另存；文件、检索、最近记录分为独立导航。开始页使用实际打开入口。
- 阅读、分栏、源码模式，源码接入主进程真实编辑稿、版本和保存服务。文档、树和编辑器独立滚动；保存/恢复及源行跳转适配新的阅读区域。
- 从实际文档生成目录，点击定位标题；阅读模式恢复目录，窄窗口收起后可显式打开。
- 统一导出对话框选择已支持的 Word/PDF，经系统保存流程执行原有隔离导出；任务窗口展示真实来源、结果及取消动作。
- 语言、缓存信息/清理与关于页进入设置；浅色/深色/跟随系统的应用外观持久化。
- 应用 UI 使用独立 `--shell-*` token 和 `.shell-ui` 选择器；文档沿用共享主题。本批验证 default/midnight 切换不改变应用栏颜色、字体和尺寸，不声称已审计全部主题。
- 快速打开搜索真实的已打开文件和最近记录，支持键盘选择及打开去重，沿用原有路径授权。
- 原生 HTML dialog 保持焦点范围与关闭返回；提供基础标签/菜单方向键、常用快捷键和专注阅读。

`shell.js` 负责应用界面，`renderer.js` 继续负责文档编排，通过窄的 `desktopApp` 接口组合；没有将样稿解析器、虚构文档或模拟导出逻辑复制为产品服务。

## 数据目录与兼容

Windows 默认数据目录为 `%APPDATA%\documd-desktop`。显式 user-data-dir 保持隔离，不自动导入个人旧数据；测试使用自有临时 profile。

首次启动且正式目录没有状态文件时，检查 `%APPDATA%\documd-desktop-prototype`、`%APPDATA%\docu.md Desktop Prototype`，仅导入结构/版本有效且大小受限的 `desktop-state.json`。设置、会话、最近记录和阅读状态保留原 JSON；缓存重新生成，不复制 Chromium profile。

采用同目录暂存、sync 和排他硬链接发布，不覆盖已有新状态，也不与旧文件共享同一 inode。旧目录与源文件保留。损坏、越界、链接或超限旧数据不自动修复/删除；文件系统不支持所需操作时提示未导入。完整手动数据恢复/升级回退界面仍待实现。

## 本轮修正

- 文件菜单项启动操作后立刻禁用，原冒泡处理漏掉收起，导致下次打开误关闭菜单。改为先消费菜单选择，再判断禁用状态；原崩溃/导出竞态测试覆盖了这条路径。
- 阅读状态和行定位改用独立 reader，继续验证真实长文切换和重启恢复。
- 视觉复查补齐阅读模式返回时的目录恢复，以及长目录标题固定。
- Windows DPI 换算存在不足两个逻辑像素的舍入；尺寸等待允许此误差，同时仍逐项检查按钮边界。

## 与完整设计的差距及后续

1. 仍是 textarea 与手动预览，草稿仅在内存；下一批重点为 CodeMirror、持续撤销/重做、查找替换、双向源行定位及异常草稿恢复。
2. 批注、完整主题/设置界面、面板拖动、完整命令列表、文件关联/单实例和拖放待完成；不展示假数据或假成功反馈。
3. 当前只接入 Word/PDF；其他保留格式、资产/表格出口、专属排版选项及细粒度任务进度按矩阵继续实现。
4. 正文排版由现有文档主题决定；完整样式边界、全部主题组合、200%/高 DPI/读屏/输入法与长译文继续验证。
5. 检索进度/性能、依赖监听、编码恢复、备份和升级回退仍需完善。
6. 开始页用于无活动文档场景；有文档时品牌入口回到阅读顶部，完整开始页标签后续补齐。
7. 25 项保留功能、排除能力最终运行时审计、真实用户文档和目标机器验收仍为发布门槛。

本批完成正式工程切换和首轮真实界面装配；完整阶段与稳定发布尚未完成。
