# Windows x64 性能与完整数据回退验证

2026-11-18，在 Windows 11 25H2、构建 26200.9974 上测试 Alpha 39 剪贴板修订包。处理器为 Intel Core Ultra 7 356H、16 个逻辑核心，系统可见内存约 31.5 GiB，主屏逻辑分辨率为 1600 × 1000、200% 缩放。系统保持联网，其他用户应用仍在运行。

受测程序来自已校验的修订便携 ZIP，应用归档 SHA-256 为 `718965f5972fbf4fc02d56f0b3e21aef139bcd44b0228d7c424a2260e88dbae4`，对应 `60663bd` 中的应用代码。各组采样依次执行，均使用合成文档和隔离配置。原生文件选择框在性能脚本内返回固定路径，计时不包含人工选文件。数据是本机观察结果。

## 启动、普通文档与取消

固定文档为 658,879 字节、3,604 行的 Markdown，无图表和外部资源。每轮使用新配置启动、打开文档，关闭文档和程序后复用配置再次启动。共五轮。新配置启动未清空操作系统文件缓存，启动时间包含测试驱动启动和连接耗时。

| 复用配置启动至可操作 | 877.9 ms | 1,078.5 ms |

取消测量在真实 DOCX 导出开始后挂起导出，以固定可取消的时点，使用实际取消路径。五轮均确认导出窗口销毁、渲染进程退出且没有成品。进程退出时间含轮询开销。上述启动、普通文档首屏和取消界面的最慢值均低于开发计划的参考目标。

## 循环开关与导出资源

保持一个含表格和 Mermaid 的参考文档，依次打开/关闭 50 份不同文档，再导出 DOCX、PDF、HTML、PNG 各五次，共 20 次，逐一核对成品签名。每十次开关和每五次导出后在空闲期取样，最后清理缓存并再次取样。

11 个检查点均为 6 个应用进程、2 个窗口和 2 个 WebContents，未遗留导出窗口。文件轮询只观察到仍打开的参考文档。合计工作集从 799.6 MiB 升至峰值 949.1 MiB，20 次导出后为 899.1 MiB，清缓存后为 900.3 MiB。阅读窗口 JS 堆从 16.3 MiB 到清理后的 17.4 MiB，中途有回落。进程工作集相加可能重复计入共享内存。本次循环没有观察到进程、窗口或文件轮询持续增加，一次循环不足以排除长期内存增长。

五轮文件名和正文搜索均扫描全部 10,000 个文件，返回预期的 100 条结果，正文查询收到 85–97 次进度更新。取消后结果为空，已打开的目录句柄全部关闭。句柄释放是本样本的后台停止观测点。

## 慢样本分段诊断

随后对原剪贴板修订包增加临时诊断，记录主进程 IPC/文件系统调用、前端预览阶段、长任务和主进程事件循环停顿。诊断代码仅在本机测试驱动内加载。

首组五轮长文切换为 95.9–170.6 ms，扩展十轮后再次复现 941.0 和 1,063.7 ms 的目标首屏等待。慢样本期间可观察到旧预览的图表 RPC 仍在执行，现有分段结果不能把全部等待都归于同一个阶段。

针对取消路径发现一个可独立复现的缺口。主进程取消了当时已进入图表队列的任务，但等待缓存读取的请求稍后仍可能启动图表渲染。回归用例固定挂起缓存读取，再取消、释放缓存，原包仍返回渲染成功。修订后为预览取消增加独立修订计数，异步等待结束时重新核对，请求已取消即拒绝继续。导出使用其原有独立任务状态。专项在原包失败，修订后的开发程序 4/4 通过，并确认后续有效渲染可以成功。

目录分页诊断有一组 7 次翻页为 4,508.2–9,251.5 ms，耗时主要落在 `readdir` 或路径解析，前端没有对应的长任务。补测 19 次翻页中 18 次为 16.2–72.9 ms，一次 2,484.8 ms；这次慢样本与主进程约 2,445 ms 的事件循环停顿重合。在同一 Electron 主进程直接读取目录的十次对照中，也有一次路径解析 3,151 ms，并与事件循环停顿重合。

独立 Node 进程的 25 次同规模目录对照未复现，路径解析最慢 1.4 ms、枚举最慢 6.2 ms。进一步 CPU 采样轮次的 19 次界面翻页为 16.7–79.4 ms，主进程 CPU 样本以空闲为主，未捕捉到能解释全部停顿的 JavaScript 热点。不同轮次之间有显著波动，尚未证明具体 Windows 调度或磁盘原因，目录慢样本继续保留。

分段证据位于 `test-results/desktop/windows-perf-diagnosis-20261118/`，包括 `long-diagnostic.json`、`long-diagnostic-expanded.json`、`paging-diagnostic.json`、`paging-diagnostic-followup.json`、`paging-cpu-profile.json`、`filesystem-control.json` 和取消回归的 `cache-cancel-before.log`、`cache-cancel-after.log`。
